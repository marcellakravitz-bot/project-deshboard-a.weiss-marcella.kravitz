# תיק מתקן — מודול נפרד באתר A. Weiss

facility build 1 · 28.10.2026 (אתר: build 224)

כל הקוד של תיק המתקן נמצא בתיקייה הזו. הדשבורד (`index.html` בשורש) רק טוען את המודול כשמנהלת המערכת פותחת את הקובייה.
הנתונים נשמרים ב-Supabase בטבלה `facility_files` (שורה אחת לכל פרויקט), למנהלת המערכת בלבד. המודול לא כותב ל-`app_state`.

## מה יש בתיקייה

| קובץ | מה זה | לאן עולה |
| --- | --- | --- |
| `admin.js` | המסך: תשעה לחצנים מרובעים, ובתוך כל אחד הצ'קליסט שלו | GitHub, `facility/` |
| `supabase/001_facility.sql` | הטבלה `facility_files` וכלל ההרשאה (מנהלת בלבד) | Supabase › SQL Editor (להריץ פעם אחת) |

מחוץ לתיקייה: `index.html` (build 224) — אצל מנהלת המערכת הקובייה "Contacts" נקראת "תיק מתקן" ופותחת את המודול; טבלת אנשי הקשר הקיימת היא פרק 1 בתוכו. קבלן ראשי ממשיך לראות את טבלת אנשי הקשר כמו קודם.

## הפרקים

1. אנשי קשר — הטבלה הקיימת, בלי שינוי
2. רשימת חומרי גמר — צ'קליסט
3. ת"י 921 + אחריות ותחזוקה — ספקים שמוסיפים ידנית (+ ספק); לכל ספק: ת"י 755, ת"י 921, כתב אחריות, פרטי מחלקת בדק, הוראות תחזוקה. לחיצה על משבצת: V ← ל"ר ← ריק. עיפרון ליד "פרטי מחלקת בדק" פותח שם / טלפון / נייד / מייל ו-PDF. אייקון המייל פותח מייל עם הנוסח (בעותק מוסתר לכל הספקים שעוד חסר אצלם ויש להם מייל)
4. אישורי מכון התקנים — צ'קליסט + הוספה
5. אישורי מתכננים — צ'קליסט + הוספה + מייל (נוסח זמני, ניתן לעריכה במסך)
6. אישורי קבלנים/מבצעים והצהרות — כמו 5
7. אישור כבאות לאכלוס — צ'קליסט
8. תיקי מתקן – קבלני מערכות — צ'קליסט + הוספה
9. תוכניות AS MADE — סימון לכל קומה; הקומות נלקחות מטווח הקומות של הפרויקט וניתנות לעריכה

בכל שורה: V צובע בירוק, "לא רלוונטי" מאפיר ומוציא מהספירה. על כל לחצן — כמה בוצע מתוך הרלוונטי.

## שמירה

שמירה אוטומטית כמעט שנייה אחרי כל שינוי, וכפתור "שמירה" בתחתית. נשמר רק מה שנערך בפועל, רק לפרויקט שנטען, ושמירה ישנה שנעקפה לא כותבת (הכלל מ-14.10.26).
